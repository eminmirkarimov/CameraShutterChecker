## ✨ Что такое Camera Shutter Checker?

Camera Shutter Checker — программа для Windows, которая анализирует метаданные фотографий и RAW-файлов и ищет записанные производителем счётчики срабатываний затвора или счётчики кадров.

В программу встроен собственный парсер EXIF/TIFF/MakerNotes. **ExifTool не требуется.** При обычной проверке файлы анализируются локально на компьютере пользователя и не отправляются на сервер.

Главный принцип: показывать значение только тогда, когда найдено распознанное поле. Если камера не записывает lifetime shutter count в файл или нужный формат не поддерживается, программа сообщает об отсутствии данных, а не угадывает пробег по имени файла.

> [!IMPORTANT]
> Единого поля пробега для всех камер не существует. Результат зависит от точной модели камеры, прошивки, формата и сохранности оригинальных метаданных. Возможность выбрать файл в программе ещё не означает, что его счётчик затвора поддерживается.

## 🧭 Матрица поддержки камер

Таблица описывает текущие ветки кода, а не гарантирует, что каждая модель была проверена на физической камере. **Практическое тестирование на данный момент проводилось на камере Sony.** Для остальных производителей уровень реализации и проверки отличается.

| Производитель | Форматы / путь метаданных | Статус | Важные замечания |
|---|---|---|---|
| **Sony** | ARW, SR2, JPEG/TIFF MakerNotes; `0x9050`, legacy-поля | 🟢 **Практически протестировано на камере Sony** | Реализованы отдельные варианты декодирования для выбранных Alpha/FX. Важны точная модель и оригинальный файл. |
| **Canon** | CR2 MakerNotes / `FileInfo`; CR3 `CMT` / `CTMD` / `CameraInfo` | 🟡 **Частичная поддержка** | Обрабатываются только отдельные модели EOS и структуры метаданных. Многие Canon не записывают lifetime shutter count в фотографию. |
| **Nikon** | MakerNotes `0x00A7` и `0x0037` | 🟡 Реализовано, проверка на камерах ожидается | Значение выводится только при наличии и доступности распознанного поля. |
| **Fujifilm** | MakerNotes `0x1438` (`ImageCount`) | 🟡 Реализовано, проверка на камерах ожидается | `ImageCount` не всегда является полным механическим пробегом и может зависеть от модели/сброса. |
| **Pentax / Ricoh** | Определённая структура MakerNotes | 🟡 Реализовано, проверка на камерах ожидается | Поддерживается конкретный известный вариант структуры, а не все камеры бренда. |
| **Samsung** | Ветка декодирования Pentax-подобных MakerNotes | 🧪 Экспериментально / не проверено | Нужны реальные образцы с физической камеры. |
| **Panasonic / Lumix** | — | ⚪ Пока нет проверенного декодера счётчика | Чтение обычных EXIF-данных не означает возможность получить пробег. |
| **OM System / Olympus** | — | ⚪ Пока нет проверенного декодера счётчика | Поддержка отдельных моделей ещё не реализована и не подтверждена. |
| **Leica и другие бренды** | — | ⚪ Пока нет проверенного декодера счётчика | Могут быть добавлены в будущих версиях. |

### Sony — текущие модельные ветки

В коде реализовано несколько структур Sony MakerNotes. Идентификаторы ниже присутствуют в логике выбора декодера, но **это не означает, что каждая камера из списка отдельно тестировалась на реальном устройстве**.

<details>
<summary><strong>Sony 0x9050 / смещение 0x3A</strong></summary>

`ILCE-7M3`, `ILCE-7RM2`, `ILCE-7RM3`, `ILCE-7RM4`, `ILCE-7SM2`, `ILCE-6100`, `ILCE-6300`, `ILCE-6400`, `ILCE-6500`, `ILCE-6600`, `ILCE-7C`, `ILCE-9`, `ILCE-9M2`, `ILCA-99M2`, `ILCE-1`, `ILCE-7M4`, `ILCE-7RM5`, `ILCE-7SM3`, `ILME-FX3`.

</details>

<details>
<summary><strong>Sony 0x9050d / смещение 0x0A</strong></summary>

`ILCE-6700`, `ILCE-7CM2`, `ILCE-7CR`, `ZV-E1`, `ILCE-1M2`, `ILCE-7M5`, `ILCE-7RM6`.

</details>

<details>
<summary><strong>Ранние Sony 0x9050a / смещение 0x32</strong></summary>

`ILCE-7`, `ILCE-7R`, `ILCE-7S`, `ILCE-7M2`.

</details>

Также есть legacy-ветка для отдельных старых камер Alpha. Структуры Sony отличаются между поколениями: модель может распознаться, но счётчик для конкретной версии метаданных может отсутствовать.

### Canon — частичная поддержка CR2 и CR3

Canon **не заявляется как полностью поддерживаемый производитель**. В программе есть отдельный разбор CR2 и CR3, однако счётчик извлекается только для некоторых моделей и вариантов метаданных.

**Canon CR3 — реализованные модельные смещения CameraInfo:**

| Семейство | Ветка в программе | Статус / ограничение |
|---|---|---|
| EOS R5 / EOS R5 C / EOS R6 | CameraInfo `0x0AF1` | Модельный алгоритм; не гарантия для всех прошивок и файлов. |
| EOS R6 Mark II / EOS R8 / EOS R50 | CameraInfo `0x0D29` | Модельный алгоритм; нужен оригинальный CR3. |
| Первая EOS R / EOS RP | Кандидатные смещения `0x0194` / `0x0960` | **Экспериментально**; значение нужно сверять с известным счётчиком этой камеры. |
| EOS R6 Mark III | Только `ImageCount` | Программа **не выдаёт его за lifetime shutter count**; значение может сбрасываться после форматирования карты. |

**Canon CR2 — отдельные старые профессиональные модели:**

Текущий парсер пытается прочитать `FileInfo` для отдельных камер поколения EOS-1D / EOS-1Ds Mark II, включая варианты Mark II / Mark II N. Для некоторых структур Mark III сомнительные значения намеренно не выводятся. Большинство потребительских EOS DSLR (например, многие 5D, 6D, 7D, xxD и Rebel) обычно не записывают достоверный lifetime shutter count в фотографию — одного файла может быть недостаточно.

> [!WARNING]
> Если Canon распознан или файл CR2/CR3 открылся, это не означает, что пробег затвора удалось прочитать. Для ряда камер требуется подключение по USB/PTP, сервисная программа или диагностика в сервисном центре.

### Как понимать результат

- **Счётчик найден** — прочитано распознанное поле. Обращайте внимание на тип: `ShutterCount`, `MechanicalShutterCount` и `ImageCount` не всегда означают одно и то же.
- **Не найдено** — поддерживаемое поле не обнаружено. Это не означает, что пробег равен нулю.
- **Модель/структура не поддерживается** — формат метаданных не входит в текущую реализацию.
- **Экспериментальный кандидат** — значение нужно перепроверить на той же камере по известному счётчику.

У разных камер механические срабатывания, электронный затвор, общее число экспозиций и последовательность файлов могут учитываться по-разному.

## ⬇️ Скачать и запустить готовую программу

1. Откройте страницу репозитория на GitHub.
2. Перейдите в раздел **Releases**.
3. Откройте самый новый релиз.
4. В блоке **Assets** скачайте `CameraShutterChecker.exe`.
5. Запустите файл на Windows 10/11 x64.
6. Выберите один или несколько оригинальных файлов либо перетащите их на программу.

**Шаблон прямой ссылки на скачивание:**

```text
https://github.com/YOUR_GITHUB_USERNAME/CameraShutterChecker/releases/latest/download/CameraShutterChecker.exe
```

Замените `YOUR_GITHUB_USERNAME` на логин владельца репозитория.

> [!NOTE]
> EXE появится в Releases после того, как разработчик соберёт и опубликует его. Исходники хранятся в репозитории, а готовый EXE прикрепляется отдельно к релизу.

## 🖥️ Запуск из исходников

Требования:

- Windows 10 или Windows 11, 64-bit.
- Windows PowerShell 5.1 для запуска исходного скрипта через BAT.
- ExifTool, Python и сторонняя утилита для чтения метаданных не нужны.
- Для обычной проверки фотографий интернет не нужен.

Порядок запуска:

1. Скачайте ZIP репозитория через **Code → Download ZIP** либо клонируйте проект.
2. Распакуйте архив.
3. Оставьте `CameraShutterCheck.ps1` и `CameraShutterCheck.bat` в одной папке.
4. Запустите `CameraShutterCheck.bat`.
5. Выберите оригинальные фото/RAW в окне выбора или перетащите файлы на BAT.

## 🛠️ Как самостоятельно собрать EXE

В проекте есть файлы:

```text
BUILD_EXE.bat
Build-EXE.ps1
```

На Windows запустите `BUILD_EXE.bat`. При первой сборке скрипт загрузит модуль **PS2EXE** из PowerShell Gallery только для компиляции. Результат:

```text
dist/
└── CameraShutterChecker.exe
```

PS2EXE нужен только разработчику для сборки. Пользователям готового EXE отдельно устанавливать PS2EXE не требуется. При этом EXE является упакованным PowerShell-приложением, а не нативной переписанной программой: он по-прежнему использует системные компоненты Windows PowerShell/.NET. Консоль оставлена включённой, потому что в ней отображается отчёт анализа.

## 📦 Автоматическая публикация EXE через GitHub Actions

В проект добавлен workflow `.github/workflows/release.yml`.

Когда разработчик отправляет в GitHub тег версии, например `v2.4.1`, GitHub Actions автоматически:

1. получает исходный код;
2. устанавливает PS2EXE на временную Windows-машину GitHub;
3. собирает `CameraShutterChecker.exe`;
4. создаёт GitHub Release;
5. прикрепляет EXE к релизу в разделе **Assets**.

Пример команд из папки проекта после настройки адреса `origin`:

```bash
git add .
git commit -m "Prepare Camera Shutter Checker v2.4.1"
git push origin main

git tag v2.4.1
git push origin v2.4.1
```

Затем откройте вкладку **Actions**, проверьте завершение сборки и перейдите в **Releases** — там должен появиться EXE. Полный пошаговый путеводитель: [GITHUB_SETUP_RU.md](GITHUB_SETUP_RU.md).

## 🔒 Конфиденциальность и файлы

- Фотографии анализируются локально.
- Программа не отправляет файлы на удалённый сервер.
- По возможности используйте оригиналы прямо с карты памяти.
- Lightroom, Photoshop, мессенджеры и социальные сети могут удалять или изменять MakerNotes при экспорте.
- Не публикуйте личные RAW-файлы в открытых Issues. Сначала согласуйте с разработчиком безопасный способ передачи образца.
